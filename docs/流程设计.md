# 编剧室重构方案 (Writer's Room Refactoring Plan)

本次重构旨在解决两个核心体验痛点：
1. **自带剧本支持**：为有自有剧本的用户提供直接粘贴入口，跳过强制的 AI 从零生成步骤。
2. **解除篇幅限制**：移除底层提示词中“只能发生在一个场景”和“只写 4-8 幕”的限制，支持自由长度和多场景跳转。

## 核心设计思路

### UI & 工作流修改 (Writer Room)

#### 1. 新增入口 (InspirationLibrary.tsx)
- 在底部增加一个「跳过AI编剧，我已有完整剧本 📝」的便捷入口。
- 点击时，直接触发 `setWriterStep(2)`，跳转到剧本编辑区，不消耗任何 API 额度。

#### 2. 快捷通道 (ScriptEditor.tsx)
- 在第二步的底部区域，为自带剧本的情况提供便捷出口。
- 在“提交评审”旁边增加一个“跳过评审，直接拆分镜 ⏩”的功能。
- 允许在没有任何 `scriptReview` (AI 打分) 数据的情况下，直接让系统将用户自带的剧本传给 `handleScriptToScenes`。

### 提示词引擎解除封印 (defaultTemplates.ts)

- **修改 `script_v1` 和 `script_to_scenes`**：
  - 删除硬性截断规则："极其重要：剧本必须非常短！总共只需 4 到 8 句对话！"
  - 改为柔性引导："支持长篇或多场景结构。请根据故事体量自然分配场景幕数。不限制最大分镜数量。"
- **修改 `script_v2`**：
  - 删除场景锁定限制："单一场景与极短对话：整个短剧（大约20-30秒）必须发生在一个固定的物理场景里。"
  - 允许场景跳转："解除单一物理场景限制，你可以根据故事情节自由切换地点和时间。"
- **【极度危险 - 必须保留的安全绳】**：
  - 尽管放开了幕数和场景限制，但必须死死保留“单句台词不超过 5 秒”的规则！这是为了防止后续视频生图和 Remotion 渲染时遭遇引擎物理极限而崩溃。

## 验收标准

1. **自有剧本流**：用户进入项目后，能一键跳过灵感库，直接粘贴几百字的长剧本，且能不经 AI 强制打分直接拆解出十几个分镜。
2. **兼容性验证**：原有的“一句话生成段子”流程不受影响，仍然能正常输出高质量的发疯短剧。
